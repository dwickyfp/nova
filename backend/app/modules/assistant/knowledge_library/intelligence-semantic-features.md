# Semantic Views and Feature Store in Nova

Keywords: Semantic View, semantic views, semantic 2.0, metrik, metric, dimension, verified query, feature store, feature view, feature group, point-in-time, training set, online features.

A Semantic View is a governed, versioned business definition over datasets, relationships, dimensions, metrics, derived metrics, hierarchies, filters, and verified questions. It gives people and agents named measures instead of asking each user to rebuild joins and formulas. Its definition uses Nova's Ossie model; the query compiler produces deterministic SQL. Nove can create one from named tables with `create_semantic_view`: it reads columns under the caller's role, generates the definition, validates it, and publishes it when valid after approval. If the table is unclear, Nove asks for it. In `/semantic-views`, users can also create a draft, inspect warnings and verified-query regression cases, and publish a reviewed version. Production queries use the active version unless a published version is pinned. Validation executes verified queries with the caller's access, compares active and candidate results, and requires explicit acknowledgement when results change. Comparison is bounded and is not a cross-version transactional snapshot.

Feature Store prepares reusable, time-aware model inputs. A Feature View defines entity keys, event time, source relation, and selected columns. Refresh creates a new materialized version; activation chooses the default. A Feature Group pins exact Feature View versions for serving and training. A point-in-time training set joins features to labels as of each label timestamp so future values do not leak into historical training rows. Lookups use the caller's source privileges. Redis can serve online values; Nova falls back to governed offline data when the cache is unavailable. The Feature Store page is `/feature-store`, alongside ML Models under Machine Learning. Online materialization and refresh are manual; scheduled refresh is not yet connected to Tasks.

Use `semantic_view_query` only when a user asks to run a published Semantic View query. It accepts metrics, dimensions, filters, named filters, an optional version, and a bounded limit. Use `feature_lookup` only when a user requests values for a named Feature Group and entity key; it accepts optional version and point-in-time timestamp. Both operations require consent. For an explanation of what a feature does, retrieve this reference without querying user data.
